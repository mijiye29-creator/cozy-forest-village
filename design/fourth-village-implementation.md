# 오로라 온천마을 구현 계획

작성: 2026-10-08 · 확장 설계 담당. **이 문서는 설계이며 네 번째 마을의 런타임 구현 완료를 뜻하지 않는다.** 기준은 `fourth-village-concept.html`과 현재 세 마을 코드다.

## 이야기와 진입

주인공은 부모님과 침대에서 책을 읽다가 마법처럼 책 속 세계로 들어온 남자아이다. 글 없는 네 장면의 인트로 뒤 숲에서 마을을 돕기 시작한다. 세 마을의 별숨맥을 복구한 뒤 광산 너머의 따뜻한 김을 발견한다. 온천마을은 책 속 다음 장이며, 집으로 돌아가는 결말을 여기서 확정하지 않는다.

최초 진입 조건은 `S.finaleDone === 1`이다. 끝판왕 전투와 기존 엔딩을 마친 플레이어가 직접 다음 여정을 선택해야 열린다. 기존 저장의 `stage:3`만으로 자동 해금하지 않는다. 해금 비용은 받지 않고, 온천 복구에서 자원을 소비한다. 게임 중 새 선택 버튼은 허용하되 인트로에는 설명 문장을 넣지 않는다.

## 단계와 복구 목표

| 상태 | 진입 조건 | 행동과 결과 |
|---|---|---|
| 잠김 | 끝판왕 미완료 | 기존 1~3마을 플레이 유지 |
| 발견 가능 | `finaleDone` | 광산 출구에서 다음 여정 선택 |
| 발견 | 직접 진입 | 온천·숙소·보일러의 고장 상태와 관리인 등장 |
| 수로 복구 | 숲 목재 납품 | 온천 물길 개방, 청록 물과 김 연출 시작 |
| 보일러 복구 | 광산 금속 납품 | 온기 생산과 시설 강화 시작 |
| 숙소 복구 | 목재와 훈제 식량 납품 | 손님 등장과 숙박 수익 시작 |
| 새 일상 | 시설 세 종류 Lv.2 + 온천 관리인 3명 | 오로라 관측지 개방, 다음 지역의 시각적 단서 |

목재·금속·훈제 식량은 현재 `ITEMS`의 실제 ID를 구현 때 연결한다. 신규 통화는 추가하지 않는다. 온기는 보일러가 만드는 마을 전용 게이지(0~100)로, 회복과 시설 연출에만 사용한다. 초기 비용안은 수로 30 목재, 보일러 20 금속, 숙소 20 목재 + 10 훈제 식량이다. 기존 창고로 달성 가능한지 시뮬레이션하고 조정하며, 희귀 재료를 필수로 요구하지 않는다.

납품은 플레이어의 보유 재료에서 정확히 차감하고 즉시 저장한다. 부족하면 차감과 단계 변경을 모두 하지 않는다. 완료 시설은 중복 구매할 수 없다. 네 번째 마을 발견 뒤에도 기존 세 마을과 직원·창고·방어 상태가 유지된다. 초기 버전에는 새 보스나 온천 습격을 추가하지 않는다.

## 저장과 호환성

현재 저장 키 `cozy-village-v6`를 유지하고 새 마이그레이션 시 `SAVE_VER`를 올려 기존 원본을 백업한다. 제안 필드:

```js
S.aurora = {
  unlocked: false,
  canal: 0,       // 0: 미복구, 1~3: 시설 레벨
  boiler: 0,
  lodge: 0,
  warmth: 0,     // 0~100으로 정규화
  crew: 0,       // 0~3명, 초기 버전 전용 관리인 수
  dailyReady: false
};
// S.storySeen[4]: 네 번째 마을 발견 장면을 읽은 경우에만 true
```

구 저장에 `aurora`가 없으면 위 기본값을 추가한다. 잘못된 필드 타입과 음수·상한 초과 값을 정규화한다. `finaleDone`이 있어도 `unlocked`는 자동 설정하지 않는다. `stage:4`는 실제 선택 시 설정한다. 현재 로드 코드가 소유 시설로 `S.stage`를 1~3으로 재계산하므로, 네 번째 마을을 열었던 저장은 그 재계산 뒤 `aurora.unlocked`를 확인해 4로 복원해야 한다. 부분 복구·읽음 상태는 재접속 후 유지하고, 중간 종료 시 재료가 두 번 소모되지 않도록 한 번의 저장 트랜잭션으로 처리한다.

## 맵과 구현 범위

현재 맵은 폭 540, `STAGE_W=[180,300,540]`, `villageAt`는 3구간에 고정돼 있다. 목표 폭은 720으로 하고 새 구간은 x=540~720이다. GC·MX·캔버스·카메라·길찾기 경계와 `areaW`의 최대 단계 제한을 함께 확장한다. 우측 구간의 위쪽은 출입구·숙소, 가운데는 수로와 온천, 아래쪽은 보일러·납품 패드로 배치한다. 시설별 통행 여유와 패드 반경을 먼저 확보한 뒤 좌표를 확정한다. 온천은 시각적 물 영역과 실제 보행 금지 영역을 동일하게 정의한다.

`villageAt`, 울타리 구간, 목표 UI, `expandStage`, 장 제목, 망루·사냥꾼의 마을별 하드코딩을 전수 점검한다. 단순히 폭만 늘리지 않는다. 관리인은 기존 사냥꾼과 분리하고 네 번째 구간의 관리 업무만 맡긴다. 기존 습격 대상 선택은 1~3구간으로 제한한다. 모바일 전체 보기에서 720 폭이 들어오고 확대 상태에서 출입구와 복구 패드에 접근 가능한지 검증한다.

## 작은 단위의 납품 순서

1. 저장 기본값·마이그레이션과 해금 조건을 추가하고 기존 저장 회귀 검증.
2. 빈 네 번째 맵·카메라·왕복 이동·충돌 경계를 구현하고 모바일 조작 검증.
3. 수로·보일러·숙소의 단발 납품과 단계별 그림 변화 구현.
4. 관리인과 온기·숙박 수익 구현, 재료 비용과 속도 조정.
5. 발견 이야기·다시 보기·후속 지역 단서 연결 후 전체 플레이 검증.

필수 인수 기준은 신규 저장에서 도달, 끝판왕 완료 저장에서 직접 해금, 3마을 저장 자동 해금 방지, 복구 후 재접속·중복 납품 방지, 기존 직원과 경제 유지, 모바일 세로·가로 접근성이다. 실기기 확인 전에는 출시 완료로 표시하지 않는다.
